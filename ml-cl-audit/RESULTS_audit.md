## 2. 预先登记的判定
**H1（原型等价）→ 判"FlyModel 被免回放原型基线超过"，三个基准一致。**
对比方按**验证集**选出（均为 SLDA）。F0 − SLDA：−0.054、−0.060、−0.131；F1 − SLDA：−0.046、−0.060、−0.099。独立审查确认方向可信。**措辞更正**：我最初把阈值内的结果写成"原型等价成立"，但数据显示的是"被超过"，等价从未被检验。
注意：SLDA 需要估计共享协方差（d²）并求逆，不是和 FlyModel 同样廉价的方法；但它同样免回放、无反向传播、与样本顺序无关。更简单的最近类均值（NCM）在弱特征上低于 FlyModel（0.60 对 0.71；0.28 对 0.34），在强特征上追平或略高（0.54 对 0.51/0.54）。

**H2（稀疏的价值）→ 登记的对照给出"有价值"，但这个对照有严重缺陷。**
登记的稠密对照（类和点积，F2）下，稀疏相对稠密的优势为 +0.562、+0.127、+0.067；F2b（论文式的稠密 min-max）恰好是随机水平（0.049、0.010、0.010），独立审查指出原因是权重饱和使全部权重为 1、argmax 并列。
**探索性对照**（非预先登记）：在**同一个**最近类均值分类器下比较稀疏与稠密扩展，优势缩到 **+0.033、+0.017/+0.023、−0.008/−0.007**。也就是说，论文式对照里几乎全部的"稀疏优势"其实是 Hebbian 类和点积规则在稠密特征上失效（我先怀疑权重饱和，探索性对照推翻了这个假设：去掉截断后稠密仍然很差，而 F0 去掉截断反而掉到 0.48）；稀疏表示本身的价值很小，在强特征上甚至略为负。

**H3（公平调参下仍优于 EWC 与小缓冲回放）→ 两种流、三个基准全部成立（门槛 0.05）。**
交错流（预先声明的扩展）：MNIST-20 +0.094；CIFAR-100 弱特征 +0.228（最佳为 ER-200 0.112，ER-1000 0.215）；强特征 +0.273（最佳为 ER-200 0.236，ER-1000 0.432，仍低于 FlyModel 0.508）。
CIFAR-100（类内顺序流，验证集选出的最佳反向传播基线）：弱特征 EWC 0.069 → F0 − best_BP = +0.271；强特征 ER-200 0.162 → +0.347；ER-1000 分别为 0.207、0.422，仍低于 FlyModel（0.340、0.508）。**重要保留**：这些反向传播基线几乎处于随机水平（0.05–0.16），与 MNIST-20 一样是类增量单遍顺序流下的灾难性遗忘（学习时准确率 0.4–0.6、最终约 0.06），说明"成立"主要反映这种流下基线的失效，而不是 FlyModel 很强；交错流下 CIFAR 的基线仍然偏低（ER-200 0.11–0.24），可能与很宽的隐层（20480）和单遍训练有关，我没有为它们做额外调参，应理解为"该预算与设定下的基线"，而不是反向传播的上限。
MNIST-20：F0 − best_BP（按验证集，ER-200）= +0.084（类内顺序流）、+0.094（交错流），超过 0.05 门槛。保留意见：
1. EWC 与微调在两种流下都基本崩溃（最终 0.05–0.10，学习时准确率 0.98 但全部学完后只剩最后一个任务），所以"优于 EWC"几乎是在比较一个失效的基线。这与近年文献中"EWC 在类增量里失效"一致，但论文自己的 EWC 在 10 类时报告为 0.58，我没有复现出那样的基线。
2. **ER-1000（0.757/0.761）高于 FlyModel（0.707），SLDA（0.760）也高于它**；FlyModel 只在对 ER-200 这一档小缓冲时占优。
3. 交错流里 ER-200 的最优学习率是 1e-5，恰好是网格的最低边缘（未继续向下试）；要让 H3 翻转，ER-200 需从约 0.61 提到约 0.66 以上，不太可能但不能排除。
4. 验证集调参只用 1 个种子。

**H4（学习量视角，仅报告）**：FlyModel、NCM、SLDA 的权重遗忘在构造上为 0（每个类的统计量互相独立，结果与任务顺序无关，`test_audit.py` 已验证）。它们的"memory loss"（约 0.09–0.14）完全来自类别数增加后的决策竞争，不是权重被覆盖。所以 memory loss 不能用来区分这些方法的"记忆保持能力"；学习时准确率（A_jj）与最终准确率才是有区分度的指标。

## 3. 这次审计中我自己造成并更正的问题
1. 结果缓存的并发丢失更新（多个进程覆盖对方条目），已改为每键一个文件并加并发测试（`DEVIATIONS.md`）。
2. 登记的流使反向传播基线在任务内第一个类上就崩溃（学习准确率恰好是 2 类随机水平），独立审查发现，我据此增加交错流并向下扩展网格；原登记结果保留并报告。
3. 复现 CIFAR-100 时我的两种特征把论文的数字夹在中间，说明论文的特征处理没写清，不能数值复现。
4. 隐层宽度实现为 40×输入维数（3360、20480），与论文的 3200、20000 略有出入，已声明。

## 4. 局限
- 只审计了一篇论文，且 CIFAR-100 的数字没有复现；
- 单一特征提取器（LeNet5 一次训练；ResNet18 预训练，CIFAR-100 与 ImageNet 语义有重叠）；
- 区间只反映种子方差（确定性方法没有区间）；
- CIFAR-100 的反向传播基线在很宽的隐层与单遍预算下偏低，不代表反向传播的上限；
- GEM 与 BI-R（论文的另外两个对手）未包含；
- 探索性对照（无截断、表示 × 分类器）是在看到结果后增加的。
