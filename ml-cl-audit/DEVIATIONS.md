# 偏离与补充（FlyModel 审计），2026-10-05
- **补充探索性对照（看到 MNIST-20 的 F2/F2b 结果之后增加，非预先登记）**：登记的稠密对照 F2、F2b 在 MNIST-20 上分别只有 0.145 与 0.049（20 类的随机水平是 0.05）。怀疑原因是 FlyModel 的权重截断到 [0,1]：稠密特征下每类的累加和很快超过 1，所有类的权重被截成同一个常数。为检验这一点，增加**无截断**变体：`Fly_dense_l2_noclip`（稠密、L2 归一化、类和不截断）与 `Fly_wta_noclip`（F0 去掉截断）。**H2 的登记判定仍按 F2 的结果给出，探索性对照单独报告并标注。**
- 为支持无截断变体，给 `cl_bench.FlyModel` 增加了可选参数 `clip`（默认 1.0，默认行为不变；已验证 F0 的结果与改动前逐位相同）。
- **饱和假设未被支持（MNIST-20，5 个种子）**：稠密+L2+不截断 `Fly_dense_l2_noclip` 仍只有约 0.11；F0 去掉截断（`Fly_wta_noclip`）从 0.7085 降到约 0.48–0.50，即截断到 1 对 FlyModel 是有益的正则（抑制累加和大的类占优）。因此论文里"稠密编码失败"更可能源于**类和点积打分规则**对稠密特征的公共偏置，而不是饱和。
- **再补充探索性对照（表示 × 分类器网格，非预先登记）**：在稠密扩展与稀疏扩展（WTA）表示上，用最近类均值（欧氏/余弦）分类，以把"稀疏表示"与"Hebbian 类和点积规则"分开。名称：`ExpNCM_{wta,dense}_{euc,cos}`。
- **设备**：反向传播基线给 `cl_backprop.run_backprop` 加了可选参数 `device`（默认 cpu，行为不变）。MNIST-20 的基线在 CPU 上跑；CIFAR-100（隐层 20000）的基线用 MPS（环境变量 `AUDIT_DEVICE=mps`）。两个设备上 `test_backprop.py` 的输出完全一致，但浮点数值在两个设备间不保证逐位相同，所以每个基准内部只用一种设备。
- **耗时风险（运行中发现）**：机器同时跑多个进程时，CIFAR-100 的单次反向传播运行约 480 秒（单遍），完整网格（B1 3 + B2 15 + B3 6+6，共 30 次调参 + 20 次终评）估计远超登记的 3 小时预算。**按登记规则，超出预算时如实报告缺失，不缩水网格。** 在 CIFAR-100 的 CPU 负载降下来之后速度会改善，再评估是否能在预算内完成。
- **缺陷：结果缓存的丢失更新（2026-10-08 发现，已修复）**：`audit_run.py` 最初把所有结果存在一个 JSON 里，每个进程在启动时读入内存、写入时整体覆盖。多个进程并发（同一基准的 proto、supp、backprop 同时运行）时，后写的进程覆盖了别的进程新增的条目。后果：MNIST-20 的 FlyModel F0 只剩 3 个种子、F1 与 6 个探索性对照整条丢失；CIFAR-100 的反向传播条目（8 与 9 个）也丢失。**此前 STATUS.md 里的"初步数字"是从运行日志读出的，不受影响。**
  修复：每个结果一个独立文件（`results/<bench>/<sha1(key)>.json`，原子写入），分析脚本按目录读取；`test_store.py` 验证 3 个并发写入者 120/120 条全部保留。旧的单文件缓存保存为 `results/<bench>.json.bak_lostupdates`，幸存的条目已迁移。丢失的条目按同样的命令补跑（缓存只补缺失项），结果以补跑后的为准。这不改变任何登记的设定或判据。

# 独立审查（verification/code_review_audit.md）之后的更正与扩展，2026-10-08
审查结论：无测试集泄漏；H1 方向可信（SLDA 在三个基准上都高于 FlyModel）；**H3 不可信**。我核实了关键事实：MNIST-20 上 B1/B2 在 lr≥1e-3 的所有配置，验证集学习准确率恰好 0.5039（2 类任务的随机水平）、最终准确率恰好 0.0500（=1/20），即网络只预测当前类。原因：登记的流把一个类的所有样本连续呈现（论文对 FlyModel 的描述），反向传播基线在任务内第一个类上就被覆盖；EWC 的 Fisher 只在任务结束时计算，无法缓解任务内遗忘。论文自己报告的 EWC 在 10 类时有 0.58，说明我的基线设定比论文的更不利。
**对登记的扩展（均在看到审查结论之后、运行扩展之前声明；原登记的结果保留并报告）：**
1. **增加"任务内交错"流变体**（`AUDIT_STREAM=inter`）：任务内所有样本联合打乱后单遍呈现。FlyModel 与样本顺序无关，所以此变体只可能有利于基线。H3 同时在两种流上报告；公平的比较以对基线更有利的那种为准。
2. **扩展调参网格向下**：学习率增加 1e-5（原 {1e-4,1e-3,1e-2}），EWC 的 λ 增加 0.1（原 {1,10,100,1e3,1e4}）。原网格的所有 MNIST 赢家都在学习率网格的最低边缘。已缓存的条目保留，只补跑新增配置。
3. **预算说明**：MNIST-20 的反向传播基线两种流都完整跑；CIFAR-100 的反向传播基线单次运行约数分钟（隐层 20480），完整网格远超登记的 3 小时预算，**按登记规则 H3 在 CIFAR-100 上如实报告为"未完成"**，仅在资源允许时再补跑交错流。
4. 分析脚本更正：H1 的措辞由"原型等价成立"改为"被 SLDA 超过（非等价）"（等价从未被检验，数据显示的是被超过）；H1 的对比方按**验证集**而非测试集选取；增加 F1 − best_P；H2 的种子配对改为按种子匹配；ep5 的键解析修正；H3 在基准或基线不全时标"未完成"而不是"不成立"。
5. **未列出的偏离（审查发现）**：反向传播基线的隐层宽度是 40×输入维数，即 3360（MNIST-20）与 20480（CIFAR-100），而不是论文与登记里写的 3200 与 20000。影响很小，但应当声明。
6. `cached()` 改为在写入前检查磁盘上是否已有该键，减少多个进程重复计算同一个键的竞争。
